1. Pourquoi VPS pour Hermes Agent

1:01 "Pour ce type d'outil, il doit tourner 24/7. Quelle est la meilleure architecture pour faire tourner ce type d'outil 24/7 ? Un VPS — parce que ça coûte très peu cher et en même temps tu as un outil qui est disponible 24/7."

Deux critères clés : (1) disponibilité permanente — les agents autonomes doivent tourner sans interruption, pas juste quand tu les utilises ; (2) coût bas — un VPS standard coûte moins cher qu'une instance cloud permanente tout en étant suffisant. Alternativement : ton ordinateur personnel (mais tu dois le laisser allumé) ou une instance cloud (plus cher). Le VPS est le sweet spot pour un agent de production 24/7 léger.

2. Les cinq fondamentaux de Hermes

6:31 "Je vais te présenter les cinq fondamentaux. Pourquoi un VPS, l'architecture cible, ce que moi j'ai mis en place et enfin les pièges à éviter."

Memory (Mémoire persistante)

6:31 "L'idée c'est de te dire : tu peux lui dire par exemple 'toi, moi, PNPM uniquement'. L'idée c'est vraiment tu lui dis ce que tu veux et il s'en souvient. Par exemple, 'arrête de faire des réponses trop longues'. Tout ça c'est important et en gros ça se base sur les préférences, les faits et les projets."

La mémoire n'est pas juste une conversation passée — c'est une base de données de préférences (PNPM is my tool), règles (answers short), faits (données sur tes projets), et historique. Hermes peut y accéder à chaque nouvelle interaction.

Skills (Capacités auto-créées)

7:02 "Il a un système de skills autocréé et raffiné par l'agent lui-même. Avec Hermes, les skills sont autocréés. Par exemple si tu fais régulièrement quelque chose... si tu publies sur les réseaux sociaux... il va voir que tu le fais souvent et il va se dire 'Bon, on va créer un skill'."

Différence clé avec Open Claw : dans Open Claw tu dois créer tes skills manuellement, ils sont statiques. Avec Hermes, l'agent détecte que tu fais une action 2-3 fois et il crée automatiquement un skill pour l'automatiser. Plus tu fais une action, plus Hermes l'optimise.

Curator Agent

8:01 "On a un curator agent, lui qui va détecter des skills qui sont pas performants."

Niveau de surveillance supplémentaire : le curator observe tes skills existants et signale ceux qui ne fonctionnent pas bien, proposant des refactos ou améliorations — automatiquement.

System Prompt (Identité & Règles)

8:34 "L'identité de ton agent, les règles. Ne fais pas ceci, ne fais pas cela, le ton, valeurs, le style, la langue. Tu peux lui dire 'réponds-moi en français', 'entrepreneur reasoning', 'pas de blabla'."

Définir la personnalité et le comportement de l'agent : langage, style d'interaction, principes éthiques, priorités (entrepreneur vs. conservative vs. creative). C'est la "constitution" de l'agent.

Plugins & Intégrations

Au lancement, tu peux configurer quels outils/APIs l'agent peut accéder (Slack, GitHub, n8n, Notion remplacé par Hermes dans ce workflow, etc.).

4. Architecture cible expliquée

Structure générale : VPS (Linux) → Hermes Agent (processus principal) → Plugins/APIs (Slack, GitHub, n8n optionnel, etc.) + Web UI (interface visuelle) + Dashboard (monitoring). L'agent tourne en arrière-plan, capable de communiquer via plusieurs canaux (CLI, Web UI, plugins) et d'orchestrer des outils externes.

5. Installation sur VPS : étapes clés

Procédure generale couverte dans la vidéo étape-par-étape :

  1. Louer un VPS (Linux recommandé)
  2. Installer l'environnement de base (Python/Node selon config)
  3. Cloner/installer Hermes Agent
  4. Configurer la mémoire et les skills initiaux
  5. Configurer les plugins (Slack, GitHub, etc.)
  6. Installer Web UI (séparé, pas intégré nativement)
  7. Démarrer l'agent en mode daemon (systemd ou similaire)
  8. Vérifier les logs et les accès

6. Configuration : Memory, Skills, System prompt

Memory

Fichier de config contenant : préférences utilisateur, règles comportementales, historique de projets. Format : YAML ou JSON selon la version de Hermes. Hermes la lit au démarrage et y ajoute des entrées au fil du temps.

Skills

Initiales : tu peux fournir quelques skills d'amorce (ex. "publier sur Twitter", "mettre à jour le backlog GitHub"). Hermes en crée d'autres automatiquement basées sur tes patterns. Chaque skill = une procédure que l'agent peut exécuter.

System Prompt

Fichier config court mais puissant : exemple donné "toi-moi direct", "entrepreneur reasoning", "français only". Cela teinte toutes les réponses et décisions de l'agent.

7. Sécurité et meilleures pratiques

La vidéo couvre la sécurité en détail (spécifique à ce contexte). Points généraux :

  • Limiter les accès des plugins (ne pas donner tous les droits à GitHub, par exemple)
  • Chiffrer la mémoire si elle contient des secrets
  • Monitorer les logs pour détecter les comportements anormaux
  • Faire des backups réguliers de la config et la mémoire
  • Mettre à jour Hermes régulièrement

8. Web UI / Dashboard / Plugins

Web UI n'est pas intégré nativement — tu dois l'installer séparément. Permet de : voir l'état de l'agent, lire les logs en temps réel, déclencher manuellement des skills, ajuster la config sans redémarrage.

Dashboard : monitoring basique (uptime, utilisation CPU/mémoire, erreurs récentes).

Plugins : interface pour ajouter de nouveaux outils. Hermes en embarque quelques-uns (Slack, GitHub, etc.), mais tu peux en écrire des custom.

9. Pièges à éviter

  • Confondre "skills" avec "plugins" — skills = procédures que l'agent exécute, plugins = outils externes que l'agent peut appeler
  • Ne pas monitorer les logs — sans logs, tu ne sais pas ce que l'agent fait ni pourquoi il échoue
  • Oublier les mises à jour — Hermes reçoit des correctifs de sécurité réguliers
  • Donner trop de permissions aux plugins — commencer petit, escalader au besoin
  • Ne pas tester en staging d'abord — lancer directement en production sans essai peut mener à des désastres

10. Checklist actionnable

1 Louer un VPS Linux (2 CPU minimum, 2 GB RAM minimum pour Hermes)
2 Installer Hermes Agent via le script official ou pip/npm selon la distribution
3 Créer un fichier memory.yaml avec tes préférences initiales (langage, priorités, règles)
4 Créer un fichier system_prompt.txt avec ton système prompt (identité, ton)
5 Installer 1-2 skills d'amorce (ex. "publier via n8n", "lire GitHub")
6 Configurer 1-2 plugins clés (Slack pour notifications, GitHub pour accès aux repos)
7 Installer Web UI et vérifier qu'elle se connecte à Hermes
8 Tester l'agent en local (staging mode) avant de passer à production
9 Configurer systemd/supervisor pour que Hermes redémarre automatiquement au reboot VPS
10 Mettre en place log rotation et backup hebdomadaire de la config + memory
11 Vérifier les logs quotidiennement pendant 2 semaines (la phase de "rodage")
12 Une fois stable, déléguer progressivement des tâches plus complexes à l'agent
