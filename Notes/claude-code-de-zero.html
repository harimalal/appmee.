1. Pourquoi Claude Code n'est pas réservé aux développeurs

0:00 "Même si vous n'avez jamais codé de votre vie, vous allez pouvoir utiliser aujourd'hui Claude Code [...] je dirais même que les gens qui en profitent le plus, c'est les non-développeurs."
6:31 "Il faut imaginer Claude Code comme un génie qui fait des choses sur votre ordinateur, qui écrit du code à votre place et vous, vous avez juste à lui parler en langage naturel français."

Argument central de la vidéo : les modèles comme Claude ont été entraînés sur énormément de code en plus du texte — puisqu'internet est majoritairement fait de code (sites, applications, systèmes d'exploitation). Claude Code ajoute une couche d'abstraction : on parle en français, l'IA traduit en langage informatique, qui est ensuite compilé en binaire. Résultat : plus besoin d'être développeur pour transformer une idée en prototype fonctionnel.

2. Premiers pas : installer l'application (pas la version web)

7:57 "Il y a un piège dans lequel tout le monde tombe [...] il y a une version de Cloud Code qui est sur le web. Et bien, c'est pas celle-là qu'il faut utiliser [...] le fait d'être sur GitHub, ça m'enlève plein de fonctionnalités."
9:11 "Cloud Code n'est pas disponible dans la version gratuite [...] uniquement accessible à partir du plan Pro Max et Max 20."

Piège n°1 identifié dans la vidéo : ne pas utiliser la version Claude Code accessible depuis GitHub dans le navigateur — elle est limitée. Il faut télécharger l'application desktop Claude depuis le site officiel. Trois onglets apparaissent une fois connecté : Chat, Cork (co-écriture), et Code — c'est ce dernier qu'il faut utiliser. Accès à Claude Code réservé aux abonnements payants (Pro minimum).

3. Exemple 1 — Créer un portfolio en mode auto

11:32 "Ce génie-là [...] il va avoir besoin d'un dossier [...] pour pouvoir bien écrire du code [...] il a besoin d'un dossier de référence, on appelle ça son dossier de travail."
14:00 "On va s'assurer que c'est bien sur auto [...] on va le laisser en mode auto pour pas à chaque fois devoir lui dire oui, oui, oui."
14:29 "Mon objectif est de me créer un portfolio et donc j'aimerais bien que tu ailles regarder mon LinkedIn ainsi que ma chaîne YouTube pour pouvoir me créer mon premier portfolio. Il faut que ça soit une page simple et que ça soit faisable assez rapidement."

Étapes concrètes : créer un dossier de travail dédié (ex. Documents/code/mon-premier-site-web), ouvrir ce dossier dans Claude Code, activer le mode auto, puis donner un premier prompt avec des liens réels (LinkedIn, chaîne YouTube) à analyser. L'agent va chercher les informations, écrit un fichier HTML (~500 lignes dans l'exemple), consomme des tokens en le faisant (~4000 tokens pour cette première tâche).

19:24 "Il a modifié mon HTML et en fait il a ajouté des lignes [...] on se rend bien compte qu'il a oublié quelque chose [...] on va devoir guider Cloud Code petit à petit."

Point réaliste : le premier résultat n'est jamais parfait — il faut itérer en donnant des retours précis (via le chat ou l'outil crayon pour cibler un élément visuel précis).

4. Déployer sur internet : GitHub puis Vercel

21:36 "Le site web, il est sous un format fichier HTML. Il faut bien aller le publier quelque part si on veut que nos utilisateurs aient accès à ça."
23:20 "GitHub est un genre de répertoire [...] dans lequel on va venir uploader nos fichiers [...] ils vont être quelque part où tout le monde peut y accéder [...] mais ce répertoire, il peut être privé."

Trois étapes expliquées et démontrées : (1) créer un dépôt GitHub privé — Claude Code peut le faire lui-même et installer les outils nécessaires (CLI GitHub) si absents ; (2) pousser le code (git push) vers ce dépôt ; (3) connecter Vercel au dépôt GitHub pour qu'il déploie automatiquement.

24:57 "Un des avantages avec Versel, c'est que une fois qu'on modifie ce fichier dans GitHub, et bien Versel l'autodéploie et ça c'est magique. Ça veut dire qu'on a pas de mise à jour à faire."
28:44 "Dès qu'on est sur https quelque chose, ça veut dire qu'on est sur internet. Si ce lien-là vous l'envoyez à un ami, ça ne fonctionnera pas [si c'est un chemin local] [...] pour qu'il fonctionne, il faut un https."

Résultat obtenu dans la vidéo : un site accessible publiquement en quelques minutes sur un sous-domaine Vercel gratuit (ex. mon-premier-siteweb.vercel.app). Étape suivante optionnelle mentionnée : acheter un nom de domaine personnalisé (~5€/an) et le connecter.

5. Exemple 2 — Une app immobilière en mode plan

31:32 "J'aimerais bien créer une application [...] pour Paris, avoir une app qui selon les quartiers [...] puisse m'afficher une espèce de map avec les prix de vente par quartier."
32:20 "Souvent c'est toujours mieux à notre génie [...] de lui dire : fais un peu le plan de ce que tu veux faire avant de commencer à bosser et écrire du code."
33:52 "Surtout, j'ai envie que tu me poses des questions avec l'outil ask user question tool tant que tu n'as pas compris mon besoin complètement."

Différence clé avec l'exemple 1 : mode plan plutôt que mode auto direct. Le prompt inclut explicitement une demande de clarification via l'outil de questions ("ask user question tool") — l'agent pose plusieurs questions précises (granularité géographique : arrondissements ou quartiers, données à afficher : prix/surface/type, usage local ou en ligne) avant d'agir. Argument donné : la majorité des projets échouent non pas par manque de compétence technique mais par manque de communication claire du besoin.

36:54 "Voici ce que source de données [...] DVF, c'est les demandes de valeur foncière, qui est un site de l'État dans lequel [...] on peut avoir département, quartier par quartier, exactement quelles ont été les dernières ventes."

L'agent identifie lui-même une source de données publique pertinente (DVF, dataset officiel de l'État français), construit un plan détaillé (architecture des fichiers), attend validation, puis exécute en mode automatique une fois le plan approuvé — téléchargement de 34 000 ventes immobilières, construction d'une carte interactive avec filtres par prix/surface.

37:31 "C'est très important de faire la planification avant le code, parce que sinon [...] les agents commencent à poser des briques parce qu'ils veulent vous montrer le premier résultat le plus rapidement possible [...] le fait de d'abord créer l'architecture, c'est beaucoup plus efficace."

Résultat : application complète avec carte interactive, filtres dynamiques (surface, prix), zoom par adresse — obtenue en une seule passe ("one shot") grâce à la planification préalable.

6. Tokens, contexte et limites d'usage

46:23 "La fenêtre de contexte [...] c'est un peu la mémoire vive avec laquelle votre Cloud Code travaille. Plus sa fenêtre de contexte va se remplir, moins il va être efficace [...] je vous inviterai à surveiller que ça va pas au-delà de 40%."
47:03 "Cette fenêtre de contexte, elle a pas juste vos messages [...] elle a aussi tous les skills, tous les outils MCP [...] plus vous allez connecter des outils, plus votre contexte sera rempli et moins votre modèle va être efficace."

Règle pratique donnée : ne jamais dépasser ~40% de remplissage de la fenêtre de contexte, sous peine de dégradation de la qualité des réponses. Chaque skill et connecteur MCP activé consomme du contexte en permanence, même sans être utilisé activement.

40:53 "La première limite qu'il y a, c'est la limite du nombre de messages envoyés [...] dans une fenêtre de 5h [...] et on a une limite hebdomadaire [...] selon si on est en pro ou en max."
42:43 "Si vous êtes en pro, vous allez avoir un carré d'utilisation. Si vous êtes en max, vous allez avoir 5 carrés [...] et avec le Max 20, vous allez avoir quatre fois l'utilisation de Max [...] c'est le plan qui coûte 200 dollars."

Structure des limites : quota sur 5h glissantes + quota hebdomadaire, qui varient selon l'abonnement (Pro < Max < Max 20 à ~200$/mois). Au-delà, passage en facturation à l'usage (API), nettement plus cher.

7. Les modèles : Haiku, Sonnet, Opus

41:40 "Haiku, ça va être le plus rapide, pas du tout adapté pour du code [...] Sonnet qui va être meilleur pour écrire du texte, peut écrire du code mais c'est pas le meilleur. Et puis Opus qui est le meilleur en ce moment [...] mais c'est aussi celui qui coûte le plus cher."

Hiérarchie donnée dans la vidéo : Haiku (rapide, économique, peu adapté au code complexe), Sonnet (bon compromis texte/code), Opus (meilleures performances, coût le plus élevé). Le choix du modèle affecte directement la vitesse à laquelle le quota d'usage se remplit.

8. Les skills : donner une compétence à l'agent

48:29 "Il y a un skill que j'adore qui s'appelle Impeccable Style [...] qui nous permet de créer des applications web et des sites web vraiment très qualitatifs [...] au lieu d'avoir ce que j'appelle du AI slop."
49:56 "Vous pouvez directement aller mettre ça dans le chat et dire : installe ce skill et ensuite utilise-le pour faire un meilleur design [...] au lieu d'utiliser le terminal."

Un skill est une compétence réutilisable, packagée et installable, qui donne à l'agent une méthode structurée pour une tâche précise (ici : le design visuel). Deux façons de l'installer : via le terminal (npx impeccable install) ou, plus simple pour un débutant, en demandant directement à Claude Code de l'installer et de l'utiliser en langage naturel.

9. Le fichier CLAUDE.md

51:35 "Ce fichier cloud.md, il va être hyper important parce que c'est le premier fichier lu par un agent Cloud Code [...] on va venir donner le pourquoi du comment de ce projet."
53:52 "Vous allez pouvoir vous-même faire générer ce cloud.md par Cloud [...] et personne pense à faire ça alors que ça nous fait gagner des performances et de la clarté."
54:03 "Un des moyens de forcer ça, c'est d'aller ici et de taper slash init [...] ça va initialiser votre fichier avec Cloud Code."

CLAUDE.md est le fichier de contexte central : identité de l'utilisateur (ex. "je ne suis pas développeur, parle-moi comme à un enfant de 5 ans"), objectif du projet, structure du code. Tout nouvel agent qui arrive sur le projet le lit en premier, ce qui évite qu'il relise inutilement toute la base de code (économie de tokens et de contexte). Se génère automatiquement via la commande /init, et peut être mis à jour à la demande.

10. Connecteurs et MCP

57:36 "Cloud peut se connecter à plein d'applications tierces comme ça. Tout ça, techniquement, c'est les MCP [...] typiquement Conto, Winzor, N8N, Clay, ou alors Interactive Brokers."
58:56 "Le modèle, ça va être un peu le cerveau de votre génie. Les connecteurs, ça va être un peu les mains [...] et les skills, c'est les recettes de comment il utilise les outils. [...] Un outil qu'il sait pas utiliser, ça sert à rien."

Métaphore retenue de la vidéo pour comprendre l'architecture : modèle = cerveau, connecteurs (MCP) = mains, skills = recettes d'utilisation des outils. Démonstration concrète avec le connecteur Tally (formulaires) : Claude Code crée directement un formulaire fonctionnel sur la plateforme sans intervention manuelle.

11. Les 4 modes de permission et la sécurité

59:41 "Il y en a un [...] demander les autorisations [...] c'est un peu le mode prudent pour débuter [...] accepter les modifications [...] Cloud modifie les fichiers tout seul mais demande pour des actions un peu risquées."
60:38 "Le mode automatique, ça c'est un peu le bon compromis [...] il avance sans vous demander mais un second modèle vérifie chaque action et bloque ce qui sort du cadre."
60:59 "Le dernier [...] il exécute tout et celui-là il est vraiment déconseillé [...] aujourd'hui il vaut mieux utiliser le mode auto."

Quatre modes classés du plus prudent au plus risqué : demander les autorisations (chaque action confirmée manuellement) → accepter les modifications (auto sauf actions risquées) → mode automatique (un second modèle vérifie et bloque les dérives, coût token légèrement supérieur) → ignorer les permissions (tout exécuté sans vérification, explicitement déconseillé depuis l'arrivée du mode auto).

61:47 "Faites très attention à vos points env [...] les clés API [...] si vous mettez ce fichier sur GitHub, tout est compromis [...] il y a plein de gens qui se font pirater comme ça à cause de leur point env qui est poussé sur GitHub."
62:15 "Faites attention à ce que vous mettez dans Cloud [...] les modèles utilisent vos données pour pouvoir être entraînés [...] si vous mettez des données très sensibles dans la conversation, ça pourra ressortir un jour."

Trois règles de sécurité explicites : (1) dépôts GitHub toujours privés par défaut ; (2) ne jamais laisser un fichier .env (contenant les clés API) être poussé sur GitHub — c'est la cause la plus fréquente de piratage citée dans la vidéo ; (3) ne jamais partager de données très sensibles dans une conversation avec un LLM, car elles peuvent réapparaître via l'entraînement futur du modèle.

12. Outils identifiés et vérifiés

Claude Code

Anthropic · Accès à partir du plan Pro (payant, pas de version gratuite) · Application desktop, pas la version web

Fonction : agent capable d'écrire, lire et modifier du code directement sur l'ordinateur de l'utilisateur, à partir d'instructions en langage naturel.

Pourquoi il est cité : sujet central de la vidéo — outil expliqué de bout en bout pour un public non-développeur.

Zed

Éditeur de code, écrit en Rust · Gratuit

Fonction : éditeur de code léger et rapide, utilisé pour visualiser les fichiers générés par Claude Code (alternative à VS Code, jugé plus lent par le créateur).

Pourquoi il est cité : vérifié réel et confirmé : GPU-accéléré, ~180 Mo de RAM au repos contre ~650 Mo pour VS Code, latence d'entrée très basse.

GitHub

Microsoft · Gratuit pour dépôts privés/publics de base

Fonction : hébergement du code sous forme de "dépôts" (repositories), pont indispensable entre l'ordinateur local et les plateformes de déploiement.

Pourquoi il est cité : étape obligatoire du pipeline de déploiement démontré dans la vidéo.

Vercel

Plateforme de déploiement · Offre gratuite disponible

Fonction : déploie automatiquement un site/app web à chaque modification poussée sur GitHub (déploiement continu).

Pourquoi il est cité : plateforme choisie pour la démo (le créateur précise utiliser personnellement Dokploy, une alternative open source, au quotidien).

Impeccable Mentionné, pas de conflit d'intérêt détecté

pbakaus (GitHub open source) · Gratuit, installation via npx

Fonction : skill de design qui donne à l'agent un véritable langage de design (23 commandes, typographie fluide, couleurs OKLCH) pour éviter l'esthétique générique "IA".

Pourquoi il est cité : vérifié réel indépendamment — dépôt GitHub actif, description cohérente avec la démonstration de la vidéo.

DVF (Demandes de Valeurs Foncières)

Data.gouv.fr · Dataset public gratuit

Fonction : base de données officielle de l'État français recensant les transactions immobilières (prix, surface, localisation).

Pourquoi il est cité : source de données trouvée et utilisée par l'agent lui-même pour construire l'application immobilière de l'exemple 2, sans intervention de recherche manuelle de l'utilisateur.

Tally

Créateur de formulaires en ligne · Offre gratuite disponible

Fonction : outil de création de formulaires, connecté à Claude Code via MCP pour générer un formulaire fonctionnel directement depuis une conversation.

Pourquoi il est cité : démonstration concrète d'un connecteur MCP en action dans la vidéo.

13. Pièges à éviter

  • Utiliser la version web de Claude Code depuis GitHub — fonctionnalités réduites par rapport à l'application desktop.
  • Se lancer sans dossier de travail dédié — l'agent doit écrire ses fichiers quelque part de structuré, sinon le système de fichiers devient rapidement le chaos.
  • Sauter l'étape de planification sur un projet complexe — sans plan préalable, l'agent construit trop vite pour montrer un résultat rapide, au détriment de l'architecture.
  • Laisser la fenêtre de contexte dépasser 40% — dégrade la qualité des réponses ; chaque skill et connecteur actif consomme du contexte en continu.
  • Utiliser le mode "ignorer les permissions" — explicitement déconseillé, remplacé par le mode automatique qui offre une vérification de sécurité pour un coût token minime.
  • Pousser un fichier .env sur GitHub — cause la plus fréquente de fuite de clés API et de piratage selon la vidéo.
  • Partager des données très sensibles dans une conversation — elles peuvent être réutilisées dans l'entraînement futur du modèle.

14. Checklist actionnable

1 Télécharger l'application desktop Claude depuis le site officiel (pas la version web GitHub)
2 Vérifier son abonnement — Claude Code nécessite un plan Pro minimum
3 Créer un dossier de travail dédié (ex. Documents/code/mon-projet) avant de lancer une session
4 Pour un premier projet simple, activer le mode auto et donner un prompt précis avec du contexte réel (liens, contenu existant)
5 Pour un projet plus complexe, utiliser le mode plan et demander explicitement à l'agent de poser des questions de clarification avant d'agir
6 Une fois le plan proposé, le valider avant de repasser en mode automatique
7 Pour déployer : demander à l'agent de créer un dépôt GitHub privé, pousser le code, puis connecter une plateforme comme Vercel
8 Lancer /init dès le début d'un projet pour générer un fichier CLAUDE.md avec le contexte du projet et vos préférences
9 Surveiller la jauge de fenêtre de contexte — ne jamais dépasser ~40% sans y prêter attention
10 Utiliser le mode automatique par défaut plutôt que le mode "ignorer les permissions"
11 Ne jamais pousser un fichier .env (clés API) sur GitHub — vérifier le .gitignore
12 Explorer les connecteurs MCP disponibles pour les outils déjà utilisés (formulaires, CRM, automatisation) avant de tout reconstruire à la main
13 Installer un skill de design (ex. Impeccable) avant de demander une interface visuelle soignée, pour éviter l'esthétique générique "IA"
